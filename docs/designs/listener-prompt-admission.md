# Design: reject invalid prompts before resident handoff

Generated by Office Hours on 2026-09-14. Mode: Builder.
Status: APPROVED under the user's instruction to make bounded builder decisions.

## Problem

An oversized Claude prompt killed an otherwise healthy resident listener.
The historical Claude tool result at 18:49:56Z reported `Wrapped prompt reaches
the native read limit` and `not queued`. Native readiness was written at
18:49:22Z, with 44 seconds remaining on the command deadline. The socket then
closed at 18:50:07Z with `idle_expired`. Pro never received this request.
The current client log was subsequently overwritten, so the preserved Claude
transcript, not that mutable log, is the evidence for the original failure.
The preserved prompt independently measures 31,907 wrapped UTF-16 units, above
the exclusive 20,000-unit limit.

## Constraints and premises

- Validate input before committing the receiver to a handoff.
- Keep exact UTF-8 bytes and the canonical wrapper's UTF-16 size accounting.
- No new send authority, queue entry, socket, timer, retry, or background service.
- Keep post-arm recovery collect-only. Preserve the old failed session untouched.
- This fixes deterministic prompt rejection, not every possible client crash.
- No changes to Pro generation deadlines or the already-installed quiet behavior.

## Alternatives

A. Increase or remove the receive timeout. Rejected: invalid input never arrives,
and an unbounded native receive conflicts with the bounded tool execution.

B. Share the canonical prompt validator with a read-only helper command, invoked
on the private bytes before rendezvous publishes any artifact. Selected: prevents
the demonstrated failure without duplicating wrapper rules in JavaScript.

C. Add cancellation packets and request-scoped receive recovery. Deferred: useful
for arbitrary client death, but a larger protocol change with late-delivery races.

## Implementation contract

Extract the existing Queue.submit input checks into one shared method. Expose
`queue check-submit` with the same input arguments; return only validation success
and `send_authorized: false`. It must not acquire a creating lock or write state.
Queue.submit must still run those same checks at actual admission.
Only deterministic input validation is shared. Mutable admission checks remain
at submission. Constructors do not write state. Helper launch failure, timeout,
malformed output, or a missing validation receipt all abort before handoff.
Exactly 20,000 wrapped UTF-16 units is rejected; test 19,999, 20,000, and 20,001.

Rendezvous checks the exact in-memory private prompt bytes through helper stdin
before writing the command ticket, command record, or starting the ready watcher.
The immutable snapshot subsequently uses those same bytes. Resume remains on its
existing canonical resume-check path. Any validation failure exits before handoff.

## Success criteria

- Oversized ASCII and non-BMP Unicode fail before any command/ready artifact,
  canonical queue entry, or transport closure.
- A valid request on the same still-unused ordinal then completes exactly once.
- Wrapper overhead and the exact 20,000 UTF-16-unit boundary use canonical logic.
- Invalid UTF-8 and identifiers fail; read-only validation creates no state.
- Existing admission, recovery, quiet runner, and full repository tests pass.

## Distribution and next action

Patch and test the isolated development candidate. Installation and live listener
readiness are distinct results, never inferred from unit tests. Do not replay the
historical request to test the change. Qualify with isolated synthetic requests.

## Open questions

General client death after ready still fails closed. A broader recovery protocol
is not required to fix this verified input-validation bug and is not included.

## Office Hours conclusion

The right problem is preventing an invalid request from consuming a live handoff,
not extending Pro's thinking time. The user's preference, "simplicity > bloatness",
supports sharing the existing validator rather than building new recovery machinery.
Companion section files are absent from the installed Office Hours skill; the
complete main skill's builder/design/review sections were used instead.

Independent design review: PASS with clarifications, 8/10. Clarified failure
handling, exact size boundary, no-write construction, and mutable admission checks.
Office Hours is complete; implementation proceeds as the separately requested patch.

## Verification

The new regression failed before the patch with `Rendezvous deadline; do not retry`.
After the patch both finite and resident variants reject oversized ASCII, non-BMP
Unicode, and empty prompts without consuming an ordinal; a valid request then
completes once. Boundary and cold-authority tests verify shared checks and no writes.
Full candidate suites: 157 Python tests and 143 Node tests passed. No live Pro send.
